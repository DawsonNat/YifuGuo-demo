# 1. 剧情原型与交互逻辑设计 (Story Prototype)

**文档目标**：将《Dropout in Silicon Valley》第五章（Jensen Hwang 的皮衣和 GPU 圣杯）转化为可执行的 Multi-Agent 交互剧本，规划 25-50 个玩家 Turn 的状态机路由，并强制植入“NPC 互相影响记忆”的核心 Feature。

---

## 一、 场景与角色设定

### 1. 场景背景
*   **地点**：NVIDIA 硅谷总部，顶层全玻璃会议室（`nvidia_hq_boardroom`）。
*   **时间**：下午 4:00，阳光刺眼。
*   **氛围**：极具压迫感。这是年轻人闯入成年人权力牌桌的时刻。

### 2. 出场角色 (Agents)
1.  **玩家 (Player)**：19 岁，刚从 UCSB 辍学，RAMUS（AI 互动内容公司）创始人。没有名校光环，只有野心和疯狂的底层算法。
2.  **Jensen Hwang (NPC 1)**：NVIDIA CEO。穿着标志性皮衣，极度聪明，极度缺乏耐心。他每天见无数个吹牛的创业者，他只为“下一个能消耗海量 GPU 的杀手级应用”买单。
3.  **Tech VP (NPC 2)**：NVIDIA 核心技术副总裁。极客，只看代码不听故事。他目前不在会议室，而在自己的独立办公室（`tech_vp_office`）。

---

## 二、 核心数值系统 (Stats)

在本次 25-50 Turn 的 Demo 中，玩家的输入将动态影响以下数值（显示在 Web 左侧面板）：
*   **Vision (愿景值)**：玩家讲故事、画大饼的能力。影响 Jensen 是否愿意继续听下去。
*   **Execution (执行值)**：玩家展现出的工程能力和底层技术硬实力。
*   **Trust (信任值)**：Jensen 和 VP 对玩家的信任度。

---

## 三、 动态路由机制与情节点设计 (The Dynamic Routing System)

**核心澄清**：本剧本**绝不是写死的线性剧情**。
Agent 的每一句话都是由大模型（LLM）根据当时的 `State`、`Memory` 和玩家的 `Query` 实时生成的。
所谓的“预定路由节点”，是指**在特定的 Turn 阈值处，系统会检查当前的数值状态，从而决定是否将世界状态切换到下一个阶段（Phase）**。

整个 Demo 预设为 4 个 Phase（阶段），由后台的状态机根据玩家的 Turn 数和数值进行动态路由。

### Phase 1：破冰与狂言 (Turn 1 - 10)
*   **当前状态 (State)**：Jensen 的 Prompt 中被注入 `{"mood": "impatient", "goal": "快速打发走这个年轻人"}`。
*   **动态交互**：玩家可以自由输入。如果玩家聊家常，Jensen 会生成极其敷衍的回复；如果玩家聊技术，Jensen 会生成质疑的回复。
*   **【路由节点 A】 (Turn 10 结束时触发检查)**：
    *   *条件判定*：系统检查玩家的 `Vision` 和 `Execution` 数值总和。
    *   *路由分支 1 (Bad End)*：如果数值未达标，系统强制注入事件（Script Event）：“保安进来请玩家出去”。Demo 结束。
    *   *路由分支 2 (推进)*：如果数值达标，系统将 Jensen 的状态更新为 `{"mood": "intrigued", "goal": "验证这个技术的真实性"}`，进入 Phase 2。

### Phase 2：技术审查与后台博弈 (Turn 11 - 25) 【核心 Feature 展示区】
*   **当前状态 (State)**：Jensen 开始认真对待，但他不会轻易相信。
*   **动态交互与核心 Feature**：
    *   在这个阶段，无论玩家输入什么，Jensen 的 Prompt 中有一条强制规则：**“遇到关键技术主张时，必须使用 `send_message` 工具向 Tech VP 求证。”**
    *   **非写死逻辑**：Jensen 发给 Tech VP 的具体问题是由 LLM 根据玩家的发言**实时生成**的（例如玩家吹嘘渲染速度，Jensen 就会问 VP 渲染速度；玩家吹嘘算法，Jensen 就会问 VP 算法）。
    *   Tech VP 也会根据 Jensen 的具体问题，调用大模型生成回复，并通过 RDC 通道发回给 Jensen。
*   **【路由节点 B】 (Turn 25 结束时，或 Tech VP 回复后触发)**：
    *   *条件判定*：检查 Tech VP 的回复是否为正面评价，且该评价是否已写入 Jensen 的 Memory。
    *   *路由分支*：一旦记忆写入成功，系统将 Jensen 的状态更新为 `{"mood": "excited", "goal": "拿下这个项目"}`，进入 Phase 3。

### Phase 3：记忆生效与态度反转 (Turn 26 - 40) 【爽点爆发区】
*   **当前状态 (State)**：基于 Tech VP 的正面背书，Jensen 的态度发生 **180 度大反转**。
*   **动态交互**：Jensen 开始主动向玩家抛出橄榄枝（如提供算力），但会附带严苛条件。玩家可以自由讨价还价。
*   **【路由节点 C】 (Turn 40 结束时触发检查)**：
    *   *条件判定*：检查玩家是否与 Jensen 达成了初步口头协议。
    *   *路由分支*：进入最终的结算谈判阶段。

### Phase 4：结局结算 (Turn 41 - 50)
*   **动态交互**：玩家与 Jensen 就对赌协议的细节进行最后的拉扯（谈判股权、算力交付时间等）。
*   **【终极路由节点 D】 (Turn 50 结束时)**：
    *   *条件判定*：根据玩家最终的 `Execution` 和 `Trust` 数值。
    *   *结局分发*：生成最终的投资条款（Term Sheet），展示 Demo 评级（如：S级 - 硅谷新星；A级 - 危险的交易；C级 - 破产边缘）。

---

## 四、 总结
1.  **剧情非写死**：所有对话均由 LLM 实时生成，NPC 之间的私聊内容也完全取决于玩家吹了什么牛。
2.  **路由节点明确**：在 Turn 10、25、40、50 设立了明确的“状态检查点（Checkpoints）”，通过修改 Agent 的内部 `State` 来引导剧情走向，完美兼顾了 LLM 的高自由度与游戏叙事的可控性。
