# 开发日志 03：Web 端 Demo 游玩形式与 UI/UX 设计方案

**记录时间**：2026-05-22

结合前期的商业目标、开发要求以及底层 `agent_world` 框架的特性，现将 Web 端 Demo 的最终游玩形式与呈现方案总结如下。该方案旨在向投资人展示“能看到世界在自行运转的沉浸式文字 RPG”。

---

## 1. 界面布局 (UI Layout)：三屏联动
为了最大化展示 Multi-Agent 的技术实力，Web 界面设计为三个核心区域：

*   **左侧 - 状态与数值面板 (Status Panel)**：
    *   实时显示玩家的 **4 大核心数值**（Vision 愿景、Execution 执行、Trust 信任、Burnout 崩溃）。
    *   显示**当前地点**（如：NVIDIA 总部顶层会议室）及**在场人物**。
*   **中侧 - 主交互区 (Main Chat)**：
    *   玩家输入文字（Typing）与 NPC 互动的核心区域。
    *   仅显示玩家能“听到”和“看到”的公开对话（基于 F2F 面对面通道）。
*   **右侧 - 上帝视角/后台监控区 (Observer Panel - 核心卖点)**：
    *   **面向投资人的“秀肌肉”区域**。
    *   实时滚动显示底层 Tick 运转流。
    *   **核心展示**：NPC 之间的**私聊（RDC 通道）**和**内心 OS（State Update）**。例如，玩家在主屏幕谈判时，右侧屏幕会实时闪过 NPC 在桌子底下的私信交流。

## 2. 核心交互体验 (UX Flow)：双段式异步响应落地
严格执行“绝不让用户干等”的要求：

*   **玩家操作**：输入对话并发送。
*   **第一段响应（< 1秒）**：
    *   前端调用 API 1，后台挂起任务。
    *   主聊天框立刻出现即时反馈（如斜体灰字：*“Jensen 停下了喝水的动作，转头看了一眼旁边的技术 VP...”*）。
*   **第二段响应（2-4秒后）**：
    *   前端轮询 API 2 获取大模型处理结果。
    *   主聊天框弹出 NPC 的正式回复，同时左侧数值面板根据剧情发生变动。

## 3. 核心 Feature 展示：NPC 影响 NPC 记忆
在 25-50 个 Turn 的游玩过程中，必须安排特定的“高光时刻”来展示 Agent 之间的交叉影响：

*   **前置铺垫**：玩家抛出硬核技术方案。
*   **内部交互触发**：NPC A 没有直接回答，而是通过私聊通道（RDC）向 NPC B 询问意见（在右侧上帝视角展示）。
*   **记忆生效与态度反转**：NPC B 的回复进入 NPC A 的 **Memory**。NPC A 根据这段新记忆，对玩家的态度发生 180 度反转（爽点爆发），从而推进剧情。

## 4. 剧情推进与路由机制 (Game Loop & Routing)
*   **游玩长度**：控制在 25-50 次 Typing（约 10-15 分钟），保证路演演示的紧凑性。
*   **路由节点设定（状态机机制）**：
    *   **节点 A（破冰）**：Turn 1-10，目标引起核心 NPC 兴趣。若数值不达标则触发 Bad End。
    *   **节点 B（技术审查）**：Turn 11-25，触发上述的 NPC 互相验证（记忆影响）环节。
    *   **节点 C（高潮/爽点）**：Turn 26-40，达成目标（如拿到投资/算力）或面临苛刻对赌。
    *   **节点 D（结算）**：根据最终数值给出结局评级。

---
**总结**：
该 Demo 表面上是一个带数值养成的文字冒险游戏，底子里是一个实时渲染的 Multi-Agent 监控大屏。它完美掩盖了 LLM 的延迟，同时直观地向投资人展示了多个 AI 智能体在同一时间流下自主思考、互相通信并改变决策的强大能力。
