# 开发日志 15：引擎未利用功能盘点与剧情扩展建议

**记录时间**：2026-05-23
**目标**：盘点 `agent_world` 引擎中存在、但目前《HBM 显存战争》剧本尚未利用的底层功能，并评估是否需要将其融入 Demo 以进一步提升展示效果。

---

经过对引擎全量源码（特别是 `script/effects/`, `agents/dynamic_tools.py`, `world/`）的深度扫描，我们目前的剧本已经使用了引擎约 80% 的核心能力（多地点、F2F/RDC/GRP 三大总线、Script 注入、状态修改、强制移动）。

但仍有以下 **5 个强大的底层功能** 处于闲置状态：

## 1. 系统全局/局部广播 (`BroadcastEventEffect`)
*   **功能说明**：允许系统向整个世界或特定房间发送一条“无发件人（Sender=-1）”的系统环境消息（如：“突然停电了”、“电视上插播了一条新闻”）。
*   **当前状态**：未使用。
*   **融入剧情建议（极力推荐）**：
    *   在 Phase 3（舌战群儒）陷入僵局时，Flask 注入一个 `BroadcastEventEffect` 到 `negotiation_room`：“*会议室的彭博社终端机突然弹出快讯：AMD 宣布下一代 MI400 芯片将采用自研显存架构...*”
    *   **效果**：这种“环境突发事件”能瞬间改变所有 Agent 的感知，逼迫三大巨头阵脚大乱，极大地增强剧本的戏剧性和不可预测性。

## 2. 动态人际关系改变 (`RelationChangeEffect` / `relation_change` 工具)
*   **功能说明**：引擎的 `RelationGraph` 支持在运行时动态添加或删除 Agent 之间的关系（如从“盟友”变成“死敌”）。这可以通过剧本强制注入，也可以由 Agent 主动调用工具触发。
*   **当前状态**：我们在 YAML 中预设了静态关系，未在运行时动态改变。
*   **融入剧情建议**：
    *   在 Phase 3 被玩家用技术逻辑击溃后，三星 CEO (Agent 6) 为了自保，主动调用 `relation_change` 工具，单方面解除与海力士 (Agent 4) 的“盟友”关系，甚至在群聊里倒戈。
    *   **效果**：完美展示 Multi-Agent 引擎中“利益同盟的动态瓦解”。

## 3. 房间氛围/规则的动态突变 (`PlaceMutationEffect`)
*   **功能说明**：允许在运行时动态修改某个地点的 `attrs`（如 `summary` 和 `behavior_hint`）。
*   **当前状态**：未使用。
*   **融入剧情建议**：
    *   当玩家在 Phase 3 抛出杀手锏技术后，注入此 Effect，将 `negotiation_room` 的 `behavior_hint` 从“充满火药味、咄咄逼人”瞬间修改为“死一般的寂静，所有人都被震撼了，说话变得小心翼翼”。
    *   **效果**：从底层规则上强制改变所有在场 NPC 的生成基调，比单点修改 Agent 状态更具全局压迫感。

## 4. Agent 自主修改内心 OS (`update_state` 工具)
*   **功能说明**：除了我们用 `StateChangeEffect` 强制改状态外，Agent 自身其实拥有 `update_state` 工具，可以根据局势**主动**改写自己的内心状态。
*   **当前状态**：目前完全依赖 Flask 层通过路由节点强制改写。
*   **融入剧情建议**：
    *   在 Prompt 中告诉 Jensen：“当你感到极度愤怒或极度兴奋时，请先调用 `update_state` 工具记录你的内心变化，然后再说话。”
    *   **效果**：在右侧上帝视角中，投资人会看到 Jensen 像活人一样，在开口前先默默更新了一句内心 OS：“这小子是个天才，我必须拿下他。”

## 5. 社交媒体平台模拟 (FEED Actions)
*   **功能说明**：引擎底层深度集成了 OASIS 社交平台，Agent 可以发推特（`create_post`）、点赞、看热搜（`trend`）。
*   **当前状态**：完全未使用（因为我们的 Demo 是封闭会议室谈判）。
*   **融入剧情建议（不推荐）**：
    *   虽然功能强大，但引入“刷推特”会严重拖慢闭门谈判的紧凑节奏，偏离“硬核技术与商战”的主题。建议在本次路演 Demo 中继续保持雪藏。

---

## 总结与决策
目前的剧本已经足够丰满。为了不过度增加开发复杂度，建议**只将第 1 点（系统广播新闻）和第 3 点（房间氛围突变）**作为“锦上添花”的彩蛋，在开发行有余力时加入 Phase 3 的高潮环节。社交媒体和复杂的关系链动态解绑可以留到未来的版本中。
