# 开发日志 04：Agent 管理机制与游戏推进逻辑 (Tick 核心闭环)

**记录时间**：2026-05-22

为了确保后续 API 开发与前端对接的准确性，现将 `agent_world` 后端对 Agent 的管理方式、Tick（时间步）的本质，以及整个游戏的推进逻辑进行详细梳理。

可以把这个框架理解为一个**“剧本杀（跑团）的桌面游戏”**。

---

## 1. 后端 Agent 的管理机制
**结论：API 不会动态生成 Agent。Agent 是“预先安排好的演员”，常驻在后台。**

*   **剧本预设（Casting）**：游戏启动时，后端会读取配置文件（如 `scenario.yaml`），一次性实例化剧本中定义好的所有角色（如：主角、黄仁勋、技术VP）。
*   **常驻内存（In-Memory）**：这些 Agent 常驻在内存中，并由 `WorldState` 统一管理。它们拥有固定的 ID、性格（Prompt）、当前位置和记忆。
*   **API 的定位**：前端调用的 API 不是用来“创建 Agent”，而是用来**“给已经存在于虚拟世界中的 Agent 传递信息”**。API 是玩家干预这个封闭世界的唯一桥梁。

## 2. Tick（时间点）的本质
**结论：Tick 不是现实世界流逝的秒数，而是回合制游戏里的“一个回合（Turn）”。**

*   虚拟世界的时间默认是**静止**的。
*   **Tick（拍）**：是一个单调递增的整型数字 `t`（0, 1, 2...）。
*   **时间推进**：只有当后台显式调用一次 `WorldStep.run_one_tick()` 时，时间才会从 `t` 变成 `t+1`。在这个瞬间，世界上所有的 Agent 才会被“唤醒”，去感知周围环境并做出反应。

## 3. 游戏推进的核心闭环 (The Game Loop)
结合我们设计的“双段式异步 API”，一次完整的玩家交互推进流程如下：

### 阶段一：世界静止
当前 `Tick = 5`。NPC（如黄仁勋和技术 VP）在会议室待机。时间静止，等待玩家输入。

### 阶段二：玩家行动（API 1 触发 - 即时反馈）
1.  玩家在 Web 端发送消息：“黄总，我的技术天下第一。”
2.  前端调用 **API 1**。
3.  后端立刻执行两件事：
    *   将这句话作为一条“面对面消息（F2F）”注入到当前地点的空气中。
    *   **立刻返回即时响应**给前端（如：“*黄仁勋正在看着你...*”），让前端 UI 动起来，避免用户干等。

### 阶段三：引擎运转（后台跑 Tick）
4.  后端在后台异步触发 `WorldStep.run_one_tick()`。
5.  **感知 (Perception)**：黄仁勋 Agent 醒来，收集到玩家刚才说的话。
6.  **思考 (LLM Call)**：黄仁勋 Agent 结合自身 Prompt 调用大模型（DeepSeek）。
7.  **行动 (Action)**：大模型返回决策。黄仁勋可能不直接回复玩家，而是调用工具给技术 VP 发送一条私信（RDC）：“查查这小子的底细。”
8.  **Tick 结束**：时间推进到 `Tick = 6`。

### 阶段四：获取结果（API 2 轮询）
9.  前端轮询 **API 2** 获取最新状态。
10. 后端返回 `Tick = 6` 发生的事情：
    *   主聊天框无更新（黄仁勋未开口）。
    *   右侧上帝视角显示：`[私聊] 黄仁勋 -> 技术VP: "查查这小子的底细。"`

### 阶段五：NPC 内部发酵与推进
11. 因为有未处理的私信，后端自动触发下一次 `WorldStep.run_one_tick()`（进入 `Tick = 7`）。
12. 技术 VP 收到私信，调用大模型思考，回复黄仁勋：“代码很乱，但底层是个天才设计。”
13. 后端再次将结果推给前端上帝视角。
14. 继续跑 `Tick = 8`，黄仁勋收到确认，终于开口对玩家说：“我给你 500 张显卡。”（前端主聊天框更新，爽点爆发）。

---
**总结**：
玩家的每一次输入，本质上是往世界里扔了一个变量，然后**手动摇了一下“时间摇把”（触发 Tick）**。在摇动摇把的回合里，所有 NPC 被唤醒，它们各自调用大模型思考、互相发消息，从而推动剧情发展。这就是 Web 端 Demo 背后真正的运行逻辑。
## 4. 补充说明：玩家 Turn 与后台 Tick 的区别 (2026-05-22 晚更新)
*   **玩家 Turn (25-50 次)**：指的是玩家在前端输入文字并点击发送的次数。这是衡量**游玩时长**的指标。
*   **后台 Tick (远大于玩家 Turn)**：
    *   玩家的一次输入（1 个 Turn），在后台可能会触发**多个 Tick** 的流转。
    *   例如：玩家输入一次 -> 触发 Tick N（Jensen 听到并私聊 VP） -> 触发 Tick N+1（VP 思考并回复 Jensen） -> 触发 Tick N+2（Jensen 收到回复并开口对玩家说话）。
    *   因此，后台的 Tick 数量是随着 NPC 内部交互的复杂程度动态增加的，绝不等于玩家的输入次数。
