# 开发日志 02：Agent World 框架源码级架构解析

**记录时间**：2026-05-22

经过对 `agent_world/` 目录下源码的详细阅读，现将整个框架的底层架构、各模块功能以及接下来的开发切入点记录如下。

---

## 1. 框架核心思想
这是一个**设计严密、高度模块化、基于 Tick（时间步）驱动的多智能体（Multi-Agent）仿真引擎**。
核心逻辑：在一个虚拟世界中，多个由 LLM 驱动的 Agent 在不同的地点（Place）活动，它们通过事件总线（Buses）进行交互，并由一个中央引擎（WorldStep）统一调度时间线。

## 2. 目录结构与核心模块解析

### 2.1 核心引擎层 (Core Engine)
负责时间流转、物理规则和状态管理。
*   **`world/` (世界状态与物理引擎)**
    *   `step.py`：**最核心的文件**。定义了 `WorldStep` 类，负责执行每个 Tick 的 11 步流水线（触发脚本、更新状态、Agent 思考、处理移动、时间推进等）。
    *   `clock.py`：全局时钟，管理当前的 Tick 编号。
    *   `state.py` / `place_store.py`：管理世界状态和所有的地点（Places）。
    *   `relation_graph.py`：管理 Agent 之间的人际关系网。
    *   `dispatcher.py`：动作分发器，处理 Agent 决定执行的动作（如移动）。
    *   `perception.py`：**感知构建器**。在每个 Tick 开始前，为每个 Agent 收集其当前能“看”到和“听”到的信息，组装成 Prompt。
*   **`buses/` (通信总线)**
    *   定义了 Agent 之间交流的通道：面对面交流（`face_to_face.py`）、带延迟的远程私聊（`remote_message.py`）、群聊（`group_message.py`）。
*   **`script/` (剧本与事件引擎)**
    *   允许预先写好剧本，在特定的 Tick 强制触发某些事件（如“第 10 拍突然停电”）。

### 2.2 智能体与大脑层 (Agent & LLM)
负责 Agent 的思考逻辑、记忆存储和大模型调用。
*   **`llm/` (大模型适配层)**
    *   完善的 LLM 抽象库，支持 OpenAI、Anthropic、DeepSeek 等。负责将感知打包成 Prompt，并解析大模型返回的 Tool Calls。
*   **`memory/` (记忆管理)**
    *   深度集成 **Zep Cloud**，负责将 Agent 每天的对话和行为进行向量化存储、检索（Retrieval）以及记忆压缩（Compressor），防止 Token 爆炸。
*   **`agents/` (智能体定义)**
    *   定义 Agent 的基础属性（`profile.py`）和可用工具（`dynamic_tools.py`）。

### 2.3 数据持久化与并发层 (Infrastructure)
*   **`persistence/` (数据存储)**
    *   `world_db.py`：基于 SQLite，将每个 Tick 的世界状态、聊天记录持久化到本地（如 `world.db`）。
*   **`ipc/` (进程间通信)**
    *   `server.py` / `client.py`：使用 IPC 机制，使得 Web API 接收请求后能异步发送给后台仿真引擎，避免阻塞 Web 服务。
*   **`pools/` & `runner/`**
    *   多池管理（接入外部平台如 OASIS）以及后台仿真引擎主循环的启动脚本。

### 2.4 应用与配置层 (App & Config)
*   **`app/` (Flask Web 后端)**
    *   `api/simulation.py`：提供对外的 HTTP API 接口。
*   **`demo/` (演示案例)**
    *   包含现有的《舔狗老公》剧本（`scenario.yaml`）和单机版运行脚本（`run_demo.py`）。

---

## 3. 我们的开发切入点 (Action Items)

底层框架（Tick、数据库、LLM 调用、记忆）已经非常坚固，**不需要**修改 `world/`、`buses/` 或 `llm/` 里面的核心代码。

**主战场在 `app/` 和 `demo/`：**
1.  **API 开发**：在 `app/api/` 下新增接口，利用现有的 `WorldStep` 和 `IPC` 机制，实现前端请求的**异步挂起**和**轮询返回**（即双段式异步响应）。
2.  **剧本开发**：在 `demo/` 下新建路演剧本（如黄仁勋对话 `jensen_scenario.yaml`），并编写对应的运行脚本或通过 Flask API 跑通该剧本。
