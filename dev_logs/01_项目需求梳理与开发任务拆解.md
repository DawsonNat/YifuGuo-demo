# 开发日志 01：项目需求梳理与开发任务拆解

**记录时间**：2026-05-22

## 1. 核心任务目标
根据与项目负责人（郭毅芙）的会议记录，本项目并非开发完整游戏，而是为了 6 月中旬美国路演和黑客松准备的 **Demo**（重点展现爆点，如黄仁勋对话或杀戮尖塔风格）。
**紧急节点**：必须在两天内完成核心 Feature，今晚 10-11 点需进行首次进度对焦（需跑通核心交互闭环）。

## 2. 核心技术架构要求
*   **运行环境**：基于 Python 3.11。
*   **驱动机制**：底层采用 Tick（全局时间单位）推进世界线。
*   **数据交互**：前后端通过 JSON 传递用户的 `Query` 和当前世界状态 `State`。Agent 接收 Query 后触发工具调用或消息传递。
*   **UX 优化核心（强制）**：必须实现**双段式异步响应**（异步消息管道），避免前端死等大模型生成：
    *   *第一段*：立刻返回即时状态/动作（如“正在思考”）。
    *   *第二段*：大模型处理完毕后返回具体执行结果。
*   **成本控制**：使用 Flash 级别模型（已配置为 DeepSeek），上下文控制在几十 K 以内。

## 3. 必须遵循的开发流程规范
*   **文档驱动开发 (Dev Docs)**：强制要求边开发边记录，沉淀为可复用的 Skill。需包含：
    1.  Story Prototype（剧情原型）
    2.  Architecture（架构设计）
    3.  Prompt 管理
    4.  测试脚本
*   **接口设计前置**：在 Plan 阶段先定义好接口功能与数据类型。
*   **代码风格**：注重实用和注解规范，不要过度追求复杂的面向对象设计（如工厂模式）。
*   **测试策略**：采用边跑边测的迭代模式。

## 4. 接下来需要进行的具体开发工作拆解
基于现有 `agent_world` 框架，接下来的工作分为以下几步：

### 4.1 编写 Dev Docs
在 `dev_docs/` 目录下新建：
*   `1_story_prototype.md`：设计“黄仁勋对话”或“杀戮尖塔”的剧情原型。
*   `2_architecture.md`：画出双段式异步 API 的架构图。
*   `3_prompt_management.md`：记录核心角色的 Persona（四段式 Prompt）。
*   `4_test_scripts.md`：记录测试双端 API 的脚本。

### 4.2 核心代码开发：实现“双段式异步响应” API（今晚生死线任务）
在 Flask 应用中实现以下逻辑：
*   **API 1 (发起交互 & 获取即时反馈)**：
    *   接收 JSON (`query`, `state`)。
    *   后台挂起异步任务，立刻返回即时响应（如 `{"status": "pending", "task_id": "123", "immediate_msg": "正在思考..."}`）。
*   **API 2 (轮询/获取最终结果)**：
    *   前端通过 `task_id` 请求。
    *   后台大模型处理完毕后，返回最终对话内容和更新后的世界状态。

### 4.3 适配 Agent 逻辑与配置新剧本
*   改造现有的同步 `DemoAgent`，使其能解析外部 API 传入的 `Query` 并调用 DeepSeek 模型。
*   新建 `agent_world/demo/jensen_scenario.yaml`，配置黄仁勋角色的属性（`agent_id`, `soul`, `long_term_goal`, `current_state` 等）。
