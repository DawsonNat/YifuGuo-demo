# 会议记录与开发要点提取

**会议主题**：AI游戏Demo开发与协作面试
**发言人**：郭毅芙、贺梁琪
**核心目标**：在两天内完成用于美国路演的 AI 游戏 Demo 核心 Feature 开发。

---

## 一、 核心技术架构要求 (Architecture & Engine)

1. **运行环境**：
   - 必须基于 **Python 3.11** 进行开发。

2. **时间与状态驱动 (Tick & State)**：
   - 底层必须采用 **Tick（全局时间单位）** 来推进世界线。
   - 前后端/模块间的数据交互必须通过 **JSON** 格式。
   - JSON 中需要包含用户的 `Query` 和当前的世界状态 `State`。
   - Agent 接收到 Query 后，其行为表现为：**触发工具调用 (Tool Call)** 或 **进行消息传递 (Message Passing)**。

3. **双段式异步响应 (UX 优化核心 - 强制要求)**：
   - **痛点**：绝对不能让用户在前端干等大模型生成长文本。
   - **解决方案**：必须实现**两次 API 调用机制**（异步消息管道）。
     - **第一段（即时反馈）**：快速返回 Agent 的即时状态/动作（例如：“正在联系某人”、“正在思考”）。
     - **第二段（最终结果）**：等大模型处理完毕后，再返回具体的执行结果或对话内容。

4. **成本与上下文控制**：
   - **模型选择**：推荐使用轻量/快速的 **Flash 模型**（如 DeepSeek 等），以控制 API 成本。
   - **Token 限制**：整体上下文长度（Context Window）必须控制在**几十 K 以内**，避免无限堆叠历史记忆。

---

## 二、 开发流程与文档规范 (Workflow & Docs)

1. **文档驱动开发 (Dev Docs - 强制要求)**：
   - 必须**边开发边记录**，将开发过程沉淀为可复用的 Skill（技能/模板）。
   - 本文档库（`dev_docs/`）后续必须包含以下四个核心模块：
     - **Story Prototype（剧情原型）**：Demo 的故事线和交互逻辑设计。
     - **Architecture（架构设计）**：系统模块如何交互、数据如何流转。
     - **Prompt 管理**：记录和维护用到的所有系统提示词和角色设定。
     - **测试脚本**：如何验证功能是否跑通。

2. **接口设计前置**：
   - 在 **Plan 阶段（写代码前）**，必须先定义好接口的功能和数据类型。

3. **代码风格提示**：
   - **注重实用**：不要过度设计，**不要**追求复杂的面向对象设计模式（如工厂模式）。
   - **注重可读性**：重点放在**功能实现**和**代码注解规范**上。

4. **测试策略**：
   - 采用**边跑边测**的迭代模式，不要等全部写完再集中测试。

---

## 三、 项目定位与交付节点 (Delivery & Mindset)

1. **抛弃“做完整游戏”的执念**：
   - 核心是 **Demo 导向**，服务于 6 月中旬的美国路演和黑客松。
   - 开发重心必须放在制造**“爆点潜力”**上（如黄仁勋对话场景、杀戮尖塔风格的卡牌/策略交互），目标是能录制出高播放量的演示视频。

2. **极高强度的自驱力要求**：
   - 开发周期极其紧急，只有**两天**时间完成核心 Feature。
   - **今晚 10-11 点是首次进度对焦节点**，必须拿出可见的进度（建议跑通双段式异步响应的骨架），这将直接决定次日的任务安排。
## 5. 新增开发注意事项与需求补充 (2026-05-22 晚更新)
*   **游玩时长控制**：Demo 整体游玩长度需控制在 **25-50 个交互回合**（Turns/Typing）内完结，保证体验的紧凑与完整。
*   **剧情节点与路由预设**：
    *   每个故事情节点（决定是否推进到下一阶段的路由节点）必须**提前预定好**。
    *   每一章的篇幅可以适当加长，且必须包含 **1-2 个“爽点”**（情绪高潮或爆点），以维持玩家的游玩动力。
*   **核心 Feature 展示（NPC 间互动与记忆影响）**：
    *   **必须重点体现**：与玩家对话的 NPC 会在某一轮次**主动去和另一个 NPC 进行交互**。
    *   这种 NPC 之间的交互必须实质性地影响目标 NPC 的**记忆（Memory）**，从而在后续剧情中产生连锁反应。这是展现 Multi-Agent 引擎能力的绝佳方式。
